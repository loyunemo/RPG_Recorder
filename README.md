# 跑团记录系统

一个面向 GM（KP / DM / 主持人）的跑团工具：**多人实时牌桌 · 骰子判定 · 战斗追踪 · 完整事件日志 · 角色卡面板**。
数据存在主持人自己的磁盘上，纯本地运行，不依赖任何外部服务。

支持四套规则：

| 系统 | 判定核心 | 关键机制 |
| --- | --- | --- |
| **克苏鲁的呼唤 7 版** | `1d100` 对比技能/属性 | 奖励骰 / 惩罚骰、三档难度、大成功与大失败、**对抗检定**、**孤注一掷**、理智与幸运 |
| **龙与地下城 5 版** | `1d20 + 调整值` 对抗 DC | 优势 / 劣势、熟练与专精、豁免、法术位、**死亡豁免** |
| **匕首心** | 双重骰 `2d12` 对抗难度 | 希望与恐惧、会心一击、压力与护甲槽打勾制、伤害阈值 |
| **华渚（中式奇幻·匕首之心）** | 同匕首心 | 13 法门 / 55 宗门流派 / 27 种族 / 15 领域 315 张领域卡、位阶、道心经历、华渚声望、九玄技 |

> 「华渚」是匕首之心的**战役扩展**而非独立规则：判定机制完全沿用，本工具据此把它实现为第四套规则集。

## 多人牌桌

主持人在自己的机器上「开启牌桌」，玩家用手机或电脑的浏览器打开同一个地址即可一起玩。
**不需要服务器、不需要注册、不需要联网**——只要在同一个局域网里。

- 主持人点顶栏「🌐 开启牌桌」，会显示一个形如 `http://192.168.1.23:41777/` 的地址，发给玩家即可
- 玩家打开地址 → 填名字 → 认领自己的角色卡 → 开始
- 掷骰、战斗推进、笔记、角色卡改动**全部实时同步**；侧栏能看到谁在线、各自拿着哪张卡
- **权限隔离**：玩家只能改自己的角色卡、只能掷自己角色的骰、不能删战役或管战斗
- **暗骰**：主持人可以把某次掷骰标为隐藏，玩家完全看不到（日志与实时推送都不下发）
- 一张角色卡同时只能被一个人认领，避免两人抢同一张卡

技术上是 **SSE 推送 + POST 上行**，没有引入 WebSocket 依赖，断线会自动重连。
牌桌未开启时，服务只接受本机请求，局域网内其他人无法访问你的数据。

## 快速开始

### 想直接用：下载安装包

到 [Releases](https://github.com/loyunemo/RPG_Recorder/releases) 下载
`RPG-Recorder-Setup-x.y.z.exe`（安装版）或 `RPG-Recorder-x.y.z-portable.exe`（便携版，免安装）。

### 想从源码跑

```bash
git clone https://github.com/loyunemo/RPG_Recorder.git
cd RPG_Recorder
npm install     # 只装一个东西：Electron
npm start       # 启动桌面应用
```

**不想装 Electron 也行** —— `npm run serve` 只用 Node.js 起一个本地服务并打开浏览器，
零 npm 依赖，功能与桌面版完全一致。这条路径同时也是多人牌桌的服务端。

```bash
npm run seed    # 可选：生成四个演示战役（四套规则各一个）
npm run serve
```

> **依赖情况**：本项目**没有任何运行时第三方依赖**，除 Electron 外只用 Node 内置模块。
> 安装细节、版本要求、国内网络镜像、常见问题、自己打包发布，
> 全部写在 **[INSTALL.md](INSTALL.md)**。

## 三个核心能力

### 1. 骰子判定

点选目标 → 设定难度与修正 → 投掷。判定规则随战役所选系统自动切换：
COC 出奖励骰/惩罚骰与三档难度，DND 出优势/劣势与 DC，匕首心出希望骰/恐惧骰与伤害结算器。

几个按规则书实现的专有机制：

- **对抗检定（COC）**：双方各掷一次 d100，比成功等级；等级相同则目标值高者胜。双方点数与判定过程会并排显示。
- **孤注一掷（COC）**：判定失败后可直接重掷，重掷前需要先写下失败的后果——这段文字会一起进日志，且与原始判定通过 `parentEventId` 关联。
- **死亡豁免（DND）**：生命值归零后的成功/失败计数与投掷，天然 20 恢复 1 点生命、天然 1 记 2 次失败，满 3 次自动判定稳定或死亡。

除规则判定外还有**自由骰式**，支持完整的骰子语法：

| 写法 | 含义 |
| --- | --- |
| `3d6` `d20+5` `d%` | 基本骰式、加减固定值、百分骰 |
| `4d6dl1` `4d6dh1` | 弃最低 / 弃最高（经典属性生成） |
| `2d20kh1` `2d20kl1` `3d6k2` | 取高 / 取低 / 取前 N 高（优势与劣势） |
| `1d6!` `4d6!!` | 爆炸骰：掷出最大值续掷并累加 |
| `2d6r1` `2d6ro1` | 重掷直到不是 1 / 只重掷一次 |
| `2d6min2` `4d6max5` | 单骰下限 / 上限 |
| `6d6>=5` `10d10cs>=8` `8d6cf<=1` | 成功计数 / 关键成功 / 净成功 |
| `4dF` | 命运骰（−1 / 0 / +1） |
| `3d6+2-1d4` | 多项加减混合 |

应用内「骰式帮助」按钮里有同一份速查表。

### 2. 战斗追踪器

「战斗」标签页负责一场遭遇战的完整流程：

- 把角色卡一键拉进战斗（自动带出生命值、AC 或闪避），或手动添加杂兵
- **掷先攻**：DND 与匕首心掷 `1d20 + 敏捷`，COC 直接按 DEX 排序
- 回合与轮次推进，当前行动者高亮，切入战斗后标签页上会显示 `R2` 这样的轮次徽标
- 每个参战者可以 −5 / −1 / +1 / +5 调整生命，或直接改数值；**PC 的生命变化会同步写回角色卡**
- 状态标记（中毒、束缚、倒地……），倒地的人自动划掉
- 战斗开始、掷先攻、伤害、倒地、每轮推进、战斗结束**全部进日志**——一场打完，日志里就是一份完整战报

### 3. 事件日志

**每一次判定、每一次改卡、每一条笔记、每一次战斗操作都会自动落进日志**，你不需要手动记。

- 按类型筛选（掷骰 / 角色卡 / 笔记 / 场景 / 场次 / 战斗）与关键词搜索
- 每一条掷骰都带**随机种子**，点「复现校验」会用同一种子重放一遍，逐位比对结果——用来确认日志没有被篡改
- 右上角随时一键**导出 Markdown 复盘**，直接就是可读的跑团记录
- 面板顶部有输入框，回车即可快速记一条事件

日志采用**追加写入**（append-only），崩溃最多丢最后一行，且永远不会被程序改写。

### 4. 角色卡面板

三套系统各有自己的卡面，派生数值全部自动计算：
- **COC 7e**：八项属性 + 派生（生命/魔法/理智上限、移动力、体格、伤害加值）+ 51 项标准技能（自动显示困难/极难档）+ 背景条目
- **DND 5e**：六维属性与调整值、AC、先攻、被动察觉、豁免与 18 项技能（熟练/专精勾选）、法术位打勾、死亡豁免追踪、特性与装备
- **匕首心**：六项属性、闪避、伤害阈值、生命/压力/护甲槽打勾格、希望与恐惧计数、9 个职业与 35 件护甲的 SRD 数据、经历、伤害结算器

角色卡上的每次修改都会作为日志事件记录，并写明**改了哪个字段、从什么改成什么**。

### 5. 按规则车卡

新建角色会走一个四步向导，**按各系统的车卡规则约束数值**：

| 步骤 | 做什么 |
| --- | --- |
| ① 基础信息 | 名字，以及系统特有的选择（COC 的职业与年龄；DND 的职业 / 种族 / 等级；匕首心与华渚的职业 / 血统 / 社群） |
| ② 属性 | 按规则生成并分配，见下表 |
| ③ 技能与领域 | 标记本职技能、选职业技能、填经历、挑领域卡 |
| ④ 确认 | 核对派生数值与资源，确认无规则冲突后建卡 |

全程显示**预算条**（还剩多少点 / 张）和**实时校验**（红色为硬性违规、黄色为提醒）。

| 系统 | 属性怎么来 | 主要约束 |
| --- | --- | --- |
| **COC 7e** | 按公式掷骰：力量/体质/敏捷/外貌/意志 = 3d6×5，体型/智力/教育 = (2d6+6)×5，幸运 = 3d6×5 | 年龄修正按规则书额度下降；技能点分「本职（教育×4）」与「兴趣（智力×2）」两笔；本职技能最多 8 项 |
| **DND 5e** | 标准数组 / 点数购买（27 点）/ 4d6 弃最低 三选一 | 12 职业的生命骰、豁免、技能表与数量；13 种族的属性加值；1 级生命值 = 生命骰满值 + 体质调整值 |
| **匕首心** | 把 +2 / +1 / +1 / 0 / 0 / −1 各用一次分配到六项属性 | 职业给出的闪避与生命点；起始希望 2、压力上限 6；护甲槽 = 护甲分数；1 级 2 条经历 + 2 张领域卡 |
| **华渚** | 同匕首心 | 法门定第一个领域、宗门定第二个领域；**领域卡只能从这两个领域里选** |

> **自定义车卡接口仍然保留。** 向导只是新建时的引导；建好之后在角色卡页可以自由修改任意字段。
> 那里会显示「偏离车卡规则」的提示，但**只是提示，不阻止保存** —— 房规、NPC、剧情需要都允许刻意偏离。
战斗追踪器对 PC 造成的生命变化同样会记录在角色卡上。

## 数据存在哪

默认写在项目下的 `data/` 目录（打包后为 Electron 的用户数据目录）。界面上「数据目录」按钮可直接打开。

```
data/
├── index.json                        战役索引
└── campaigns/<战役 id>/
    ├── campaign.json                 战役元数据
    ├── sessions.json                 场次索引
    ├── state.json                    可变状态：当前战斗序列、上次选中的角色
    ├── characters/<角色 id>.json      角色卡（一卡一文件）
    └── log/
        ├── <场次 id>.jsonl            该场次的事件日志
        └── _campaign.jsonl           战役级事件（建卡、删卡等）
```

日志是纯文本 JSONL，可以直接用编辑器翻阅。**备份 = 复制整个 `data/` 目录。**
想换位置，设环境变量 `RW_DATA_DIR` 指向别处即可。

### 加一套新规则

在 `src/core/rulesets/` 下新建一个模块，导出这几个成员即可，界面会自动生成对应的角色卡与判定面板：

```js
export default {
  id, name, short, accent, dieIcon,
  createDefault(name),        // 新建角色卡的初始数据
  derive(data),               // 返回 { tracks, stats }，界面据此渲染资源条与派生数值
  rollTargets(data),          // 返回可判定的目标分组，界面据此生成按钮
  roll(data, req, rng),       // 执行判定，返回带 detail 与 seed 的结果对象
  initiative(data),           // 可选：先攻推导，返回 { kind:'static'|'roll', ... }

  // 可选能力，界面按存在与否决定是否显示入口
  supportsOpposed, rollOpposed(data, req, rng),   // 对抗检定
  supportsPush,                                   // 失败后可孤注一掷（复用 roll 的 request）
  supportsDeathSave, deathSave(rng, state),       // 死亡豁免
};
```

然后在 `src/core/rulesets/index.js` 里注册一行。

## 已知取舍

- **多人限于同一局域网**。没有做公网穿透、房间码和账号体系——家用跑团够用；要联外网得自己配内网穿透。
- **玩家不能新建角色卡**，只能认领主持人建好的。这是有意的：角色数据由主持人把关。
- **骰式不支持括号与乘除**。目前是扁平的四则加减结构，覆盖跑团常见需求；要加表达式树得改 `dice.js` 的解析部分。
- **匕首心本身不规定先攻**，战斗追踪器用 `1d20 + 敏捷` 作为可选方案；想按剧情顺序行动就手动填先攻值。
- **怪物没有独立卡面**。战斗里可以用「手动添加」记录杂兵的生命与 AC，但没有完整的怪物数据块（建议后续补）。
- **华渚的宗门设定集未收录**。docx 里「华渚宗门」一章约 1700 行是世界观设定而非规则数据，本次没有提取。
- **未打包成安装包**。目前 `npm start` 直接运行；要出 `.exe` 需再引入 electron-builder。

### 华渚框架里原文含混、本工具未擅自消解的地方

提取时发现若干规则表述不完整或有冲突，一律照原文实现并在界面上标注，没有替作者「修好」：

- **道心经历给的是 −2**，而匕首之心的经历通常是 +2；用它掷骰会让结果变差。界面上的数值可直接改。
- **「将希望骰变为 20」**：希望骰是 d12，20 超出上限。疑似笔误，未改。
- **归藏炁墟漏了消耗数字**（其余八技都是「1 点希望点」）。
- **受通缉倒计时的方向**疑为写反（「大于当前倒计时则用它替代」会加速通缉）。
- **九玄技在文中出现两次且内容不同**（玩法版与考据版），两版都保留着。
- **位阶是等级区间**（如贯枢境＝2–4 级），而「心魔横生」要求「掷出数量等同于位阶的 d20」，没有单一数字可用——本工具取区间。
- 另有若干错别字与标点残缺（如「狮王门」引用了不存在的「狮子吼」特性）一律照录。
